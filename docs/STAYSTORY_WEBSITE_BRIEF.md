# StayStory Website Redesign — Master Project Brief

> This is the governing brief for all StayStory website work: homepage, the StayStory
> Method page, Platform pages, About / Story, Pricing, and any supporting pages added
> as the site evolves. It sits alongside `STAYSTORY_OPERATING_SYSTEM.md`, which governs
> product, philosophy, and voice. Where this brief covers website structure and visual
> direction, it is the source of truth.

We are restructuring and redesigning the StayStory website.

This is **not** a complete rebrand. StayStory already has an established visual identity,
product concept, tone, and design direction. The goal is to improve the site's:

- Structure
- Hierarchy
- Clarity
- Product storytelling
- User journey
- Visual consistency
- Conversion flow

The finished website should feel like one cohesive StayStory system, not a collection of
individually designed pages.

---

## Core Brand Idea

StayStory helps hospitality operators intentionally design the guest experience.

The platform helps hosts move beyond simply asking *"What else should I add?"* and instead
begin asking *"What do I want guests to feel, remember, and talk about?"*

StayStory combines guest-experience thinking, hospitality strategy, storytelling, and
practical tools into one connected system.

The ultimate goal is to help hospitality operators design stays that feel intentional,
personal, memorable, consistent, distinctive, and worth returning to.

---

## Website Strategy

The website should progressively help a first-time visitor understand:

1. What StayStory is
2. What it helps them accomplish
3. How the system works
4. Why the approach is different
5. What the actual product looks like
6. What they ultimately receive
7. Whether StayStory is right for someone like them
8. What happens when the system works
9. What action they should take next

**Do not try to answer all of these questions inside one section.** Each section should
have one clear job.

---

## Homepage Strategy

The homepage should remain concise and product-led. Its current planned structure is:

1. Hero / Value Proposition
2. Platform Overview
3. Why Hosts Choose StayStory / Benefits
4. Proof / Results
5. Built for the Way You Host / Audience
6. Final CTA

The homepage should provide enough for a visitor to understand StayStory without forcing
them to read the entire philosophy behind it. Deeper ideas live on supporting pages.

---

## Supporting Page Philosophy

Supporting pages let us go deeper without making the homepage overwhelming.

**The StayStory Method** — the problem; the shift in thinking; why experiences matter; the
StayStory Method; the Experience Compass; the Guest Journey Playbook; why the method works.

**Platform** — individual product components; product functionality; product interfaces;
how the tools connect; the Guest Journey Playbook; deeper product demonstrations.

**About / Story** — founder story; origin of StayStory; Laurel & Lore; hospitality
philosophy; research and influences; bigger-picture thinking.

**Pricing** — pricing tiers; included features; objections; FAQ; conversion-focused CTA.

Do not force deeper supporting-page content back onto the homepage unless specifically
requested.

## Approved Visual Direction

The StayStory website should combine **modern SaaS clarity** with **premium hospitality
warmth**.

The site should feel: calm, refined, editorial, modern, spacious, premium, human,
thoughtful, sophisticated but approachable.

The site should never feel: cold, overly technical, corporate, generic, like a template
startup website, like a generic AI product, or like a traditional hotel website.

### Core Visual Language

- Clean white or warm off-white backgrounds
- Deep navy typography
- StayStory purple / indigo accents
- Muted lavender
- Soft aqua or teal accent details
- Subtle gradients when appropriate
- Elegant editorial headline typography
- Clean sans-serif supporting copy
- Rounded product/interface containers
- Light borders
- Soft understated shadows
- Generous whitespace
- Clear section separation
- Refined iconography
- Strong but restrained CTA styling

Use decorative elements sparingly. The design should feel polished without becoming
visually busy.

### Important Visual Rule

**Do not use photography simply because there is empty space.** Photography should only
appear when it adds real meaning.

Prioritise: product previews, interface mockups, journey diagrams, experience diagrams,
editorial typography, icons, cards, visual comparisons, guest quotes, intentional
whitespace.

When photography is used it should have a specific purpose. Avoid filling multiple
sections with decorative property photography — it crowds the page and distracts from the
core message.

---

## Product Visuals

StayStory should feel like a real, tangible product. Where appropriate, use **editable
product-preview containers** to show: Experience Audit, Experience Compass, Experience
Blueprint, Generator, Story Builder, Guest Journey Playbook, dashboard views, guest
journey visualisations, experience planning tools.

These visuals should look sophisticated but must never be permanently baked into the
layout — we need to replace them later with real screenshots or updated interface designs.

---

## Editable Website Requirement

**This is extremely important.** All significant website content must remain editable.

Do not create flattened designs in which text, imagery, and interface visuals become one
permanent static image. Build content as reusable, editable components.

We need the ability to change: headlines, supporting copy, labels, CTA text, CTA
destinations, icons, product names, product descriptions, product screenshots, images,
guest reviews, ratings, statistics, audience categories, section order, card order.

Where appropriate, components should also be reorderable, removable, addable, and reusable
elsewhere on the site.

---

## Product Components

The current StayStory system includes:

- Experience Audit
- Experience Compass
- Experience Blueprint
- Generator
- Story Builder
- Guest Journey Playbook

**These names and structures may continue to evolve. Do not assume they are permanent.**
Build layouts so components can be renamed, reordered, added, removed, or rewritten
without requiring a complete redesign.

### Guest Journey Playbook

Currently the primary output of the StayStory system. Present it as the place where the
work created throughout StayStory comes together. It should feel useful, tangible,
shareable, living, practical, and connected to the entire guest journey.

Do not present the Playbook as an unrelated feature. Where appropriate, visually show
other StayStory tools contributing to or flowing into it. Its name and positioning may
evolve, so all related copy must remain editable.

### Experience Compass

The Compass should not feel like a forgotten fifth feature. Its conceptual role is to
establish *what should this experience feel like?* and give direction to later decisions.

Where appropriate — especially on the StayStory Method page — show the Compass as a
guiding layer or thread keeping the whole experience aligned.

---

## Copy Style

StayStory copy should be clear, warm, intelligent, human, specific, confident, concise,
and emotionally aware.

Avoid: corporate jargon, excessive SaaS terminology, generic marketing claims, buzzwords,
overly long paragraphs, abstract philosophy without practical meaning, overly sales-driven
language.

Explain StayStory in plain language first. The visitor should not have to understand
hospitality theory before understanding the product.

---

## Claims and Proof

**Do not invent statistics, customer numbers, testimonials, results, ratings, or business
claims.**

If a claim is not yet verified, use an editable placeholder, neutral wording, or temporary
copy. For example, do not permanently state *"Join thousands of hosts"* unless that claim
is supported.

When guest reviews from Laurel & Lore are used, clearly explain that Laurel & Lore is the
property where the StayStory thinking/system was developed or tested.

Stay transparent about what is guest proof, customer proof, product proof, and future
placeholder content.

## Navigation

Current top-level navigation direction:

- Platform
- The StayStory Method
- Why StayStory / About, depending on final structure
- Pricing
- Login
- Start Free

Labels may continue to evolve. Maintain consistency across all pages.

---

## CTA System

Use a consistent CTA hierarchy across the website.

- **Primary:** Start Free
- **Secondary:** See the Platform · Explore the Platform · Explore the Method

Avoid adding unnecessary competing actions. CTA treatment should stay consistent in
colour, shape, spacing, typography, hover behaviour, and mobile behaviour.

Where appropriate include reassurance microcopy — *No credit card · Setup in minutes ·
Cancel anytime* — and keep it editable.

---

## Responsive Design

Every section and page must be designed for desktop, tablet where relevant, and mobile.

**Do not simply shrink the desktop layout for mobile.** Preserve the hierarchy and
storytelling sequence.

For mobile: stack content intentionally, keep CTA buttons easy to tap, keep product
visuals readable, maintain generous spacing, keep headlines from becoming overly tall,
preserve the logical reading order.

---

## Accessibility and Usability

Maintain strong text contrast, readable type sizes, clear focus states, accessible
buttons, appropriate alt-text capability, logical heading hierarchy, comfortable line
lengths, and clear clickable areas.

Visual sophistication should never reduce usability.

---

## How We Will Work

We build the website **page by page and section by section**. Do not redesign an entire
page unless explicitly asked.

For each section there are typically two instructions:

1. **Section Build Prompt** — purpose, content, copy, components, editable requirements,
   responsive behaviour, relationship to surrounding sections.
2. **Visual Mockup Prompt** — composition, layout, spacing, visual hierarchy,
   product-preview placement, design treatment, reference mockup.

When a visual reference is supplied, use it as the primary visual source of truth. Do not
reinterpret an approved mockup unless explicitly asked.

### Critical Rule for Existing Approved Mockups

If an approved StayStory mockup already exists: **preserve what is working.**

Do not automatically simplify, remove, combine, or reinterpret sections. Only change the
specific elements requested.

If asked to remove decorative photography, increase whitespace, change a component name,
restack content, or make elements editable — make those changes while preserving the rest
of the approved design.

**Do not use a small revision request as permission to redesign the entire page.**

---

## Final Standard

Every page should feel like it belongs to the same StayStory website.

A visitor moving between the homepage, Platform, the StayStory Method, About, and Pricing
should experience the same brand, typography, spacing logic, colour system, button system,
interface treatment, voice, and level of polish.

The finished StayStory website should feel intentional in exactly the same way StayStory
asks hosts to design their guest experiences.
